## Matching contract

Both present customer IDs take precedence over email. Equal IDs match even when the event email changes or is absent. Different IDs never match merely because email agrees. When either ID is absent, the existing case-insensitive email fallback remains. A matching legacy row with no stored customer ID still receives the supplied ID as a backfill.

The helper can return the truthy string `superseded` for an email match with conflicting IDs. The `=== true` check is essential: coercing its result to a boolean or using a truthy check would retain the defect. No new matching implementation is copied into tests.

The helpers are shared with risk and review branches as well as invoice branches. This change applies the same identity rule at those existing call sites.
