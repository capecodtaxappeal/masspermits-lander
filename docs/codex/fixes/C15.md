## Risks and limits

The intended behavior change is limited to unavailable/invalid roster data and thrown ZIP get failures. Callers now see a retryable 503 for those conditions. The response still uses the existing suggestion to try the emailed attachment.

The response streams the artifact body. A later stream failure after the handler has returned cannot be converted into a 503 by this catch. No buffering or synthetic promise of stream recovery was added. Roster body parsing remains inside the existing catch. The fix does not validate ZIP contents, establish freshness, repair roster data, or prove live R2 reliability.

The offline harness uses selected local workerd contract checks; it does not certify the full Cloudflare platform or inbox receipt. Mission tests remain frozen pending the owner's branch.
