## Scope and exact contract

Branch: claude/codex-fix-c18-preconditions. Base: e4f913765f7c241505fcff959d1617114dfedcea. The only production file changed is functions/api/upload-bundle.js. This is the optional-precondition portion of C18/I23, not closure of the entire publication finding.

An authorized PUT or POST may omit preconditions, or supply exactly one If-Match or If-None-Match header. A supported value is the unquoted wildcard `*` or one nonempty strong quoted ETag. Surrounding header whitespace is ignored. The implementation strips the outer quotes and forwards the opaque tag unchanged to R2 `onlyIf.etagMatches` or `onlyIf.etagDoesNotMatch`.

| Caller condition | Result when condition holds | Result when it fails |
| --- | --- | --- |
| If-Match with strong tag | Replace only the object with that current ETag | 412; missing or different object is preserved |
| If-Match wildcard | Replace any existing object | 412 when absent |
| If-None-Match with strong tag | Write when absent or current ETag differs | 412 when current ETag matches |
| If-None-Match wildcard | Create only when the key is absent | 412 when it already exists |
| No precondition | Existing unconditional PUT/POST behavior | Existing storage-error handling |

The conditional path performs one R2 put. It does not read before writing, retry without a condition, or interpret an attempted conditional put as a committed replacement. An R2 null result becomes `412 {"ok":false,"error":"precondition failed"}`. Success preserves the exact JSON shape `{ok:true,key,bytes}` and adds the stored object's HTTP ETag response header. A thrown storage error remains a 500.

Empty, bare, weak, multi-tag, malformed and quoted-wildcard values are rejected with 400 before storage. Both ETag headers together and the unsupported If-Modified-Since, If-Unmodified-Since and If-Range headers are also rejected. Quoted `"*"` is excluded so a literal tag cannot accidentally acquire SDK wildcard semantics. This is a deliberately bounded HTTP precondition interface; it does not implement every standard conditional-header form.

Authentication, PUT/POST restriction, nonempty-body check, 25 MiB maximum, nine intended keys and their content types are unchanged. The inherited-key gate problem C17 is left to its separate draft. No read endpoint or read allowlist is widened.

## Compatibility, remaining work and risk

The existing weekly-refresh workflow bundle/status/health uploaders, cold-outreach log uploader, and cold_sender.py state uploader send no conditional headers. Their request bodies, methods, content types and success-JSON expectations are preserved. No workflow or consumer was changed or executed. The endpoint capability alone does not protect current publication. A later caller change must carry the appropriate previously observed tag, handle 412 as a conflict, and never silently retry unconditionally. An unconditional writer can still overwrite a conditional writer. Wildcards test existence only, and an ETag describes object bytes rather than a publication run. This change does not make multiple uploaded keys a transaction, establish generation ordering, validate ZIP/JSON content, or solve C17/C19. The fixed part prevents a stale supported conditional request from silently succeeding; broader C18 remains partial.

Risk is concentrated in callers that were already sending ignored conditional headers: they now receive enforced 412 outcomes or an explicit 400 for unsupported forms. All inspected existing consumers are unconditional. A 412 must be handled as a visible conflict, not as successful delivery or permission to discard the condition. There is no new configuration or credential requirement.
