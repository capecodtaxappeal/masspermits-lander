Put your town’s building permits on your own site

One line of HTML shows recent building-permit activity for a Massachusetts town — how many, which trades, the median declared value, and the latest filings with house numbers removed. It costs nothing, loads nothing from anyone but us, sets no cookie, and refreshes itself every week without you touching the page again.

Built for the people already publishing about their own town: chambers of commerce, town news sites, realtors, supply houses, trade associations, building-department pages. Currently 77 locations — 57 municipalities, 6 Cape villages and 14 Boston neighbourhoods. Massachusetts has 351 municipalities, so most of the state is not here; a widget pointed at a town we do not publish says exactly that, and why.

What it sends, and what it does not

  • No cookie, no storage, no fingerprint, no third party. The widget loads two files from masspermits.com and nothing from anywhere else — no font, no image, no framework, no analytics vendor.
  • One count per view. We record which town was shown and the domain of the site showing it. Not the page, not the query string, not the visitor. It is the same first-party counter every page on masspermits.com uses, and it is the only way we can tell whether this reaches anyone. data-analytics="off" turns it off.
  • Nothing is written to your page. The script creates one iframe and sets its height. It reads no other element and defines no global but its own.
  • Clicks are marked. Links back to masspermits.com carry utm_source=widget, so widget traffic can be told apart from search traffic.

What is in it — and what is deliberately not

The widget publishes exactly what our open-data catalog and public feeds already publish for free: trade, issue date, street name with every house number removed, and the declared project value. It never publishes a contractor, an owner, a house number or a permit number — the build aborts rather than emit one.

Every figure is computed from the corpus at build time, and the rule behind each one is published. evidence.json carries the gates, the thresholds, the row-cap detection and the per-location table behind the list below. index.json is the machine-readable manifest. Each location’s payload sits at /widget/v1/data/<slug>.json with CORS open — you are welcome to build your own thing on it instead of using ours.

  • Median declared value is shown only where at least 8 permits in the window carry a value above zero. Many Massachusetts sources record a literal 0 or 1; those rows are excluded and counted, never averaged in.
  • Some sources cap what they hand us. Where a count is a ceiling rather than a total, the widget shows “at least N” and says why.
  • The window ends at that location’s newest record, not at today’s date. A town whose records stopped in July reports a July window with its real dates, instead of an empty “this month”.
When a town goes dark, the widget tells your visitors before we can tell you. On 1 August 2026 a records vendor cut off anonymous access and 117 Massachusetts towns stopped publishing to us overnight. An embed pasted into a page in March is one we can never edit — so the embed is not what decides what to say. Each location’s data file carries its own dates, and past 60 days with no new record the widget replaces its counts with a coverage notice, on every page that embedded it, with nobody touching those pages. A location we drop is never deleted; its file is replaced with the reason.

Questions

What does the widget cost?

Nothing. It is free to embed on any site under CC BY-NC 4.0, which requires attribution and rules out reselling the data itself.

Which Massachusetts towns can I embed?

57 municipalities plus 6 Cape villages and 14 Boston neighbourhoods - 77 locations in all, each with at least 15 recent permits. Massachusetts has 351 municipalities, so most of the state is not here; a widget pointed at a town we do not publish says so and gives the reason, rather than showing an estimate.

What happens if a town stops publishing?

The widget starts saying so on its own. Every embed loads its figures from masspermits.com at view time, and each location's data file carries its own freshness dates. Past 60 days with no new record the counts are suppressed and a coverage notice is shown instead - on every page that embedded it, without those pages being touched.

Does the widget track visitors?

It sets no cookie, reads no storage and identifies nobody. It records one count per view - which town was shown and the domain of the site showing it - so we can tell whether the widget reaches anyone. Add data-analytics="off" to switch that off; everything else works identically.

Where do the numbers come from?

Public municipal building-permit records, recomputed at build time. Every gate, threshold and per-location figure is published at /widget/v1/evidence.json, and each location's payload is at /widget/v1/data/<slug>.json with CORS open.

Your town isn’t listed

Then we do not publish it, and a widget pointed at it will say so and give the reason we recorded when we surveyed how that town publishes — a vendor portal that will not answer anonymous requests, a building department that keeps paper only, or a source we have simply not built a reader for yet. That is a real finding about the town, not a gap in this page; the survey behind it is in our coverage analysis. If you know a public source we have missed, tell us — that is the fastest way for a town to appear here.
